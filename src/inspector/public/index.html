Context Window Architecture · draft

What did CWA assemble, and why?

One support question runs through the Python, TypeScript and Go assemblers on the same frozen inputs. The app never assembles anything itself: it freezes inputs, hands them to an assembler, compares what comes back byte for byte, and shows every decision on one screen.

Start with the basic stage about twelve minutes per stage
Every stage page has these four columns
1
Candidate context
what the producers sent, colored by outcome
2
CWA decisions
the trace: included, compressed, excluded, and why
3
Outbound request
the payload, or no request at all
4
Model answer
a live call, the exact request beside it
That view separates a producer error from an assembler error from an adapter error from a model error.

“Check my entitlement, investigate this incident, and draft the next action.”

Three MCP servers propose tools, the capability policy grants some, the guard authorizes every request before a call, and each observation enters the next inference as evidence. Recorded runs replay through all three assemblers.
